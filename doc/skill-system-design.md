# 技能系统设计与首个技能实施计划

> 状态：实施计划。第一阶段只加入玩家主动技能「跳跃」，但数据与流程必须能够容纳后续职业技能。

## 首个垂直切片：跳跃

| 项目 | 规则 |
| --- | --- |
| 技能 ID | `jump` |
| 名称 | 跳跃 |
| 类型 | 主动技能、目标位置技能 |
| 射程 | 8 格，按施放者与目标格的切比雪夫距离计算；跳跃无视路径与中间地形。 |
| MP 消耗 | 50 MP；当前 MP 不足时不可施放。 |
| 冷却 | 8 个后续玩家回合。施放完成后设为 8，之后每完成一个玩家回合减 1；减至 0 才能再次施放。 |
| 目标合法性 | 目标格必须在射程内、已被玩家看见、且为可站立地形。目标格可被敌人占据。 |
| 无敌人目标 | 玩家落到目标格。 |
| 有敌人目标 | 对该敌人造成 400 威力伤害；若击杀敌人，玩家直接落在目标格；若敌人存活，玩家落到目标格周围最近的可站立、未被敌人或物品占据的空格。 |

### 落点与失败规则

- “最近”按目标格的切比雪夫距离从近到远搜索；同距离时按固定的八方向顺序选择，确保存档重放和测试结果稳定。
- 对敌人目标先结算伤害，再决定落点：敌人死亡后其格子成为落点；敌人存活时才搜索周围空位。
- 搜索半径限制为本次跳跃的射程 8 格；若敌人存活且范围内不存在合法空位，技能不可施放，不消耗 MP、不进入冷却，也不消耗回合。
- 玩家不能落在墙、地图外、敌人、物品或出口以外的不可站立格上。
- 若目标格没有敌人，目标格本身即是落点，故不需要额外搜索。

## 威力与伤害结算

普通攻击定义为 **100 威力**。跳跃为 **400 威力**，即在伤害公式的“动作基础威力”阶段采用普通攻击的 4 倍。

```text
普通攻击：动作威力 = 100
跳跃：    动作威力 = 400

动作基础攻击 = 主属性攻击力 × (动作威力 / 100)
后续结算 = 敌方防御 -> 信念 -> 直击 -> 暴击
```

跳跃与普通攻击共享职业主属性、信念、直击、暴击和敌人防御的结算逻辑；技能威力只替换动作的基础攻击部分。这样 400 威力是可解释的伤害比例，而不是固定数值伤害。

## 最小数据模型

第一阶段不建立完整的技能树或效果脚本系统，只新增以下可扩展的公共字段：

```ts
type SkillId = 'jump';

interface SkillDefinition {
  id: SkillId;
  name: string;
  targetType: 'position';
  range: number;
  mpCost: number;
  cooldownTurns: number;
  potency: number;
}

// 玩家运行时状态
skillCooldowns: Record<SkillId, number>;
```

职业定义保存可用技能列表；本阶段龙骑士仅拥有 `jump`。冷却为运行时状态，必须进入存档；技能静态配置不进入存档。

## 交互与状态流

```text
玩家点击“跳跃”或快捷键
  -> 进入目标选择状态，渲染 8 格可选范围
  -> 点击目标格
  -> 校验 MP、冷却、距离、可见性、地形、落点
  -> 进入“技能动画中”状态并锁定其他输入
  -> 起跳/滞空/落地/命中演出结束
  -> 扣除 MP、写入冷却、结算伤害与位置
  -> 敌人行动，技能冷却在之后的玩家回合递减
```

- 目标选择状态允许取消，不消耗资源或回合。
- 技能动画中不得保存为可继续操作的中间状态；如页面刷新，保留施放前状态或在动画开始前完成一次原子结算，具体实现采用后者：先提交完整的逻辑结果，再由渲染层播放短暂演出并锁定输入。
- 施放成功消耗一个正常玩家回合，因此会触发敌人行动、MP 自然回复、Buff 倒计时和死亡判定。

### 释放 UI 与图标资源

- HUD 增加技能栏；第一阶段仅显示一个“跳跃”技能按钮，显示图标、名称、MP 消耗、冷却剩余回合与不可释放状态。
- 玩家点击技能按钮或使用预留快捷键后进入目标选择状态；再次点击或按取消键退出选择。
- 目标选择期间，地图需显示 8 格范围提示，并分别区分合法落点、敌人目标与不可选择格。
- 图标按技能 ID 加载，跳跃图标固定路径为 `public/assets/skills/jump.png`；运行时 URL 为 `/assets/skills/jump.png`（兼容项目部署基路径时使用现有 `BASE_URL` 拼接）。
- 已创建资源目录：`public/assets/skills/`。图标缺失时按钮保留文字“跳跃”作为降级显示，避免阻断技能使用。

## 动画方案

现有渲染层每帧可叠加临时显示对象，伤害数字已有短动画模式。跳跃演出应新增独立的临时动画层，不把动画坐标写入永久玩家状态：

1. 从施放前坐标生成英雄残影或精灵副本。
2. 以抛物线在约 300–450 ms 内移动到目标/落点；中点略缩小或淡出，表现离地。
3. 落地时播放短暂冲击效果；命中敌人时同步触发 400 威力伤害数字。
4. 动画结束后移除临时对象，解除输入锁定。

动画层必须与逻辑结算解耦：伤害、死亡、击杀奖励和目标进度在一次状态更新中完成，演出仅用于表现已确定的结果。

## 实施步骤与验收

1. **技能数据与存档**：增加 `SkillDefinition`、龙骑士跳跃定义、玩家冷却字段与版本迁移。
   - 验收：新旧存档均能加载；冷却值在保存/读取后不变。
2. **公共威力结算**：抽取普通攻击与跳跃共享的威力伤害函数。
   - 验收：100 威力保持现有普通攻击结果；400 威力使用同一套属性、直击与暴击规则。
3. **目标与落点判定**：实现射程、可见性、地形、敌人格与最近空位搜索。
   - 验收：墙、不可见格、MP 不足、冷却中和无落点均不消耗资源/回合；有敌人与无敌人的落地规则正确。
4. **回合与冷却**：接入施放动作、MP 消耗、冷却、敌方行动和冷却递减时点。
   - 验收：施放后冷却为 8；恰好经历 8 个后续玩家回合后可再次施放。
5. **UI 与动画**：增加技能按钮/快捷键、图标资源加载、范围高亮、目标取消、冷却与 MP 不足反馈、跳跃演出。
   - 验收：动画期间输入锁定；动画结束后地图、HUD 与战斗日志一致。
6. **自动化测试**：覆盖上述规则以及 400 威力、击杀奖励、连续升级、存档和边界落点。

## 本阶段不做

- 多职业技能、被动技能、技能升级树和通用效果脚本。
- 技能公共资源以外的职业资源消耗。
- 多目标、范围伤害、障碍物破坏、位移碰撞与反应技能。
