# 基准层地图模板设计

> 状态：提案
>
> 用途：作为最基本的一层地图模板，验证房间、过道、回路、入口和出口的核心体验。

## 1. 模板目标

基准层不追求复杂的分支和特殊地形，只验证一张地图是否具备基本的探索选择：玩家从入口房出发，可以沿回路的不同方向前进，也可以进入少量支线房间获取战斗和资源内容。

硬性要求：

- 房间总数为 3–5 个。
- 至少 1 个大房间。
- 至少 2 个小房间。
- 至少 3 个房间构成一个闭合回路。
- 回路不固定为 3 个房间，可以覆盖 3、4 或 5 个房间。
- 回路内部允许出现穿行过道，作为捷径或额外连接，从而形成更复杂的路线结构。
- 初始位置必须位于回路上的房间内部，不能位于过道或回路外的支线房间。
- 所有房间和过道均必须从入口可达。

本模板的核心不是某一组固定房间编号，而是一个“至少 3 个房间的环形子图”。房间数量增加时，优先允许回路本身变大，而不是只把房间全部作为支线挂在一个固定三角形外面。

## 2. 房间图拓扑

### 2.1 回路长度

设地图房间总数为 `N`，回路房间数为 `K`：

```text
3 ≤ K ≤ N ≤ 5
```

`K` 个回路房间按顺序排列为 `L0 ... L(K-1)`，并连接成环：

```text
L0 ── L1 ── L2 ── ... ── L(K-1)
 \______________________________/
```

其中最后一条边连接 `L(K-1)` 和 `L0`。因此：

- `K=3` 时是最小三房间回路。
- `K=4` 时可以形成四房间回路。
- `K=5` 时可以形成五房间回路，所有房间都在回路上。

回路上的房间必须是不同的房间，不能通过同一房间内部的多个连接点伪造回路。

### 2.2 房间数量和回路变体

第一版可以从以下变体中按 seed 选择：

| 房间总数 | 允许的回路房间数 | 结构示例 |
| ---: | --- | --- |
| 3 | 3 | 3 个房间全部组成回路 |
| 4 | 3、4 | 三房间回路 + 1 个支线，或四房间回路 |
| 5 | 3、4、5 | 三房间回路加 2 个支线、四房间回路加 1 个支线，或五房间回路 |

建议初始阶段先使用均匀随机的 `N=3..5`，再在调试中允许固定 `N` 和 `K`。这样可以分别验证最小回路、大回路和带支线的回路。

### 2.3 支线房间

当 `K < N` 时，剩余的 `N-K` 个房间作为支线房间接入回路：

- 每个支线房至少连接到一个回路房。
- 第一版默认每个支线房只连接一次，形成回路外的树枝。
- 支线房不能替代回路中的任意一条边。
- 支线房可以位于回路外侧，但不能挤入回路内部并切断回路过道。
- 后续如果需要更复杂的地图，可以为支线房增加第二条连接，使其成为第二个回路；这不属于基准层的默认结构。

因此，在没有中穿过道时，基准层的房间图边数为：

```text
回路边数 K + 支线边数 (N-K) = N
```

它至少有一个回路；如果增加中穿过道，边数会超过 `N`，回路数量也会增加。

## 3. 中穿过道与额外连接

“中间出现穿行小道”不应作为随机挖墙的副作用，而应被定义为一种明确的连接类型。

### 3.1 中穿过道

中穿过道是位于回路包围区域内部、连接两个已有区域的过道，可以有两种形式：

1. **回路弦边**：连接两个不相邻的回路房间，例如四房间回路中的 `L0-L2`。
2. **过道捷径**：连接一条已有回路过道的中段与另一个回路房间或另一条过道。

第一版优先实现回路弦边，因为它可以直接用房间图表示、容易验证，也能产生明确的第二条捷径。过道捷径可以在后续加入过道交叉点数据后实现。

### 3.2 中穿过道规则

- `K=3` 时默认不生成弦边，避免最小地图过度拥挤；如要增加复杂度，可生成过道捷径。
- `K>=4` 时允许以 20%–35% 的概率生成 1 条弦边。
- 弦边必须连接两个不相邻的回路房间，不能重复已有回路边。
- 弦边优先穿过回路包围的中央空间，不能穿过第三个房间内部。
- 弦边可以与既有过道交叉；交叉处视为可通行的过道节点，而不是墙体重叠错误。
- 生成器必须记录弦边，使测试能够区分“设计出的额外连接”和“意外挖通”。

如果加入 1 条弦边，房间图的环路数从 1 增加为 2。基准层不限制环路数量必须恰好为 1，只要求至少为 1。

## 4. 房间角色与尺寸

基准层默认只有 1 个大房间，其他房间为小房间。大房间必须优先放在回路上，使其成为探索过程中的枢纽或目标房，而不是孤立的支线终点。

| 角色 | 类型 | 尺寸建议 | 说明 |
| --- | --- | --- | --- |
| 入口房 | 小房间优先 | 4–6 × 4–5 | 初始位置，不能被普通敌人包围 |
| 回路普通房 | 小房间 | 4–6 × 4–5 | 回路中继、普通战斗或资源 |
| 回路大房 | 大房间 | 8–10 × 6–8 | 枢纽、特殊敌人、重要物品或目标 |
| 出口房 | 小房间或大房间 | 4–10 × 4–8 | 默认位于回路上，放置出口 |
| 支线房 | 小房间 | 4–6 × 4–5 | 可选战斗、物品或事件 |

房间角色不再绑定固定编号。生成器应先确定回路，再从回路房间中选择入口房、出口房和大房间：

- 至少一个回路房间被标记为大房间。
- 至少两个房间被标记为小房间；如果回路只有 3 个房间，则这两个小房间也应优先位于回路上。
- 入口房必须是回路房。
- 出口房默认是不同于入口的回路房。
- 大房间不能被安排在入口出生格上。

## 5. 物理布局

基准层使用当前 32×32 地图，外围保留 1 格墙。

### 5.1 回路房间布局

先按回路顺序把 `K` 个回路房间放置在一个不规则环形区域上：

- `K=3`：形成三角形或弯曲三边形。
- `K=4`：形成四边形或不规则菱形。
- `K=5`：形成五边形或弯曲环形。

这些名称只描述空间趋势，不要求房间中心严格落在规则多边形顶点上。每个中心点都允许有 seed 驱动的随机偏移，但必须满足：

- 相邻回路房之间有足够空间放置过道。
- 首尾回路房 `L(K-1)` 和 `L0` 也能连接，不能只满足相邻顺序而漏掉闭合边。
- 房间中心不能近似全部共线。
- 回路内部保留一块可用于中穿过道的空间；如果没有生成弦边，仍保留中央空间作为视觉上的回路内部。

### 5.2 支线房间布局

支线房间放在回路外侧，并通过最短方向连接到一个回路房。支线房不应放在回路内部，否则会遮挡中穿过道并破坏回路的可读性。

### 5.3 过道硬约束

- 过道宽度默认为 1 格。
- 每条回路边都必须从源房间进入目标房间至少 1 格。
- 回路边的非房间部分不能完全与另一条回路边重合。
- 过道可以交叉或复用已有过道，但不能让两个不同的房间图边只剩同一条物理路线。
- 过道不能穿过第三个房间内部；经过已有过道或在过道交叉点汇合是允许的。
- 所有房间与过道地块都必须保持 4 方向可达。

## 6. 入口、出口与内容规则

### 6.1 初始位置

入口房从回路房间中选择，初始位置必须满足：

- 位于入口房的房间地板内部。
- 不位于过道、支线房或中穿过道。
- 不与敌人、物品或出口重合。
- 优先选择房间中心；中心不可用时选择距离中心最近的可用格。

入口房可以是回路上的任意房间，不再固定为某个编号。生成器只需要保存 `entranceRoomId` 和 `loopRoomIds`，并验证入口房属于回路集合。

### 6.2 出口

基准层默认将出口放在入口所在回路的另一侧房间：

- 出口房必须是回路房，且不能与入口房相同。
- 优先选择沿回路距离入口最远的房间；存在多个候选时随机选择。
- 出口位于房间内部，不放在过道末端。
- 出口附近至少保留 2×2 的可移动空间。
- 出口格不被敌人或物品占用。

由于入口和出口都在回路上，玩家至少可以沿回路的两个方向探索。支线房和中穿过道为可选路线，不应破坏这两条基础路线。

### 6.3 内容分布

- 入口房不放普通敌人，避免玩家出生即受攻击。
- 大房间承载 1–2 个普通敌人、特殊敌人、重要物品或楼层目标中的一种或多种。
- 出口房保持出口周围空间清晰，可放置少量内容但不能堵住出口。
- 支线房优先放置可选战斗、物品或事件。
- 第一版不在普通过道中随机刷敌人和物品；中穿过道只承担路线和空间节奏。

## 7. 生成顺序

1. 从 seed 决定房间总数 `N`，范围为 3–5。
2. 从 `3..N` 决定回路长度 `K`，并创建 `loopRoomIds`。
3. 生成 `K` 个回路房间的尺寸、中心点和矩形。
4. 依照回路顺序连接 `L0-L1`、`L1-L2`，直到 `L(K-1)-L0`，形成闭合回路。
5. 如果 `N>K`，创建剩余支线房间，并各自连接到回路房。
6. 如果 `K>=4` 且命中概率，增加 1 条回路弦边或中穿过道。
7. 为回路房间选择入口房、出口房和大房间角色。
8. 生成入口格、出口格、敌人和物品。
9. 对房间图和实际地板分别执行连通性、回路和内容容量验证。

生成失败时应丢弃整张布局并使用下一个确定性的重试种子重新开始，不能在已生成的地图上随机补洞。保底布局也必须满足“至少 3 个房间回路”，不能退化成单房间或树状地图。

## 8. 运行时数据结构

房间编号不表达固定角色，布局应显式记录回路和连接类型：

```ts
type ConnectionKind = 'cycle' | 'branch' | 'chord' | 'shortcut';

interface RoomConnection {
  fromRoomId: number;
  toRoomId: number;
  kind: ConnectionKind;
  corridorId: number;
}

interface MapLayout {
  rooms: RoomLayout[];
  corridors: CorridorLayout[];
  connections: RoomConnection[];
  loopRoomIds: number[];
  entranceRoomId: number;
  exitRoomId: number;
  roomIdByCell: (number | null)[];
  corridorIdByCell: (number | null)[];
}
```

`loopRoomIds` 是回路房间集合，长度必须满足 `3..rooms.length`。`connections` 中 `kind='cycle'` 的边必须按照 `loopRoomIds` 首尾相连；`branch` 是支线；`chord` 和 `shortcut` 是可选的中穿过道。

第一阶段可以只在生成和测试期间保留 `MapLayout`，不写入 `FloorState`，以免立刻修改存档格式。地图移动仍以 `tiles` 为最终地形来源。

## 9. 验证规则

基准层必须通过以下硬性验证后才能返回给 `generateFloor`：

1. 房间数量在 `[3, 5]` 内。
2. 大房间数量至少为 1，小房间数量至少为 2。
3. 回路长度 `K` 满足 `3 ≤ K ≤ 房间总数`。
4. `loopRoomIds` 中的房间互不重复。
5. 回路边按 `loopRoomIds` 首尾闭合，且每条边都有独立的房间连接记录。
6. 房间图整体连通。
7. 房间图环路数至少为 1；加入弦边时允许大于 1。
8. 入口房的 ID 位于 `loopRoomIds` 中。
9. 初始格位于入口房内部，不在过道或支线房。
10. 出口房是不同于入口房的回路房，并且出口可达。
11. 所有实际可通行地块都能从入口通过 4 方向 BFS 到达。
12. 回路边不能完全共享同一条物理过道。
13. 房间、敌人、物品、入口和出口之间没有非法重叠。

房间图的环路数可以用以下公式检查：

```text
环路数 = 边数 - 节点数 + 1
```

当没有中穿过道时，基准层通常满足 `边数 = 节点数`，因此环路数为 1；当加入一条弦边或捷径时，环路数至少为 2。无论哪种情况，都必须通过 `loopRoomIds` 的显式回路验证。

## 10. 测试用例

建议新增 `baseline-floor-template.test.ts`：

- 抽样 500 个 seed，房间数量始终为 3–5。
- 抽样 500 个 seed，至少 1 个大房间和 2 个小房间。
- 回路长度始终为 3–5，且不超过实际房间数。
- 每个 seed 都存在至少 3 个不同房间组成的闭合回路。
- 强制 `K=3`、`K=4`、`K=5` 时，三种回路规模都能生成成功。
- 每个 seed 的入口房都属于 `loopRoomIds`，初始格在该房间内。
- 每个 seed 的出口房是入口之外的回路房。
- 每个 seed 的所有地板都可由入口 4 方向到达。
- 强制启用中穿过道时，新增连接被记录为 `chord` 或 `shortcut`，且不会破坏基础回路。
- 删除任意一条基础回路边后，其他回路边仍能保持回路房间的整体连通。
- 相同 seed 生成完全相同的房间图、回路集合、房间矩形、过道和入口位置。

## 11. 与后续楼层模板的关系

基准层不是最终所有楼层都必须使用的固定布局，而是地图生成器的最小合格模板。后续楼层可以在保留同样数据结构和验证器的前提下变化：

- 增加房间数量。
- 增加回路长度。
- 增加第二条或第三条环路。
- 增加更多中穿过道和过道交叉点。
- 把任意回路大房改成特殊敌人房或 Boss 房。
- 把支线房改成商店、事件或资源房。

但只要某个楼层声明使用“基准层模板”，就必须严格遵守本文件中的 3–5 房间、至少 3 房间回路和入口回路约束。
