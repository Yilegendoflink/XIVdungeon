# 玩家 RPG 属性设计方案

> 状态：第一版属性模型与 0.1 龙骑士奖励池已落地。本文定义当前原型的属性字段与伤害/资源结算；技能的逐项规则见 `doc/skill-system-design.md`。完整公式索引见 `doc/formula-reference.md`。

## 目标与边界

本方案用于承载职业差异、技能取值、资源循环与局内构筑。属性分为动态资源与静态属性两层：

- **动态资源**在战斗或回合中变化，必须保存当前值与上限（无上限时例外）。
- **静态属性**是角色的基础战斗参数，由职业、成长、装备、状态效果等来源汇总；它们不直接作为可消耗资源。
- 本方案已替代“普通攻击只使用 `atk`”的原型逻辑；敌人的 `atk` 与 `def` 仍作为敌方战斗数据保留。

## 动态资源

| 资源 | 必有 | 数据要求 | 规则职责 |
| --- | --- | --- | --- |
| HP | 是 | `current`、`max` | 承受伤害；`current` 降至 0 时，本轮冒险失败。 |
| MP | 是 | `current`、`max` | 通用法术及职业技能的基础消耗资源。其回复速度与消耗修正受信仰影响。 |
| 职业特殊资源 | 按职业定义，可有 0 种或任意多种 | 稳定 ID、名称、`current`、可选 `max`、获得与消耗规则 | 表达职业独有循环，例如层数、槽位、充能、姿态计量等。 |

### 职业特殊资源约束

- 职业资源以列表保存，不以固定字段集合保存，保证职业可自由增加资源种类与数量。
- 资源 ID 在同一职业内唯一，并应作为存档、技能条件和效果引用的稳定键；名称只用于展示。
- 有上限的资源必须限制在 `[0, max]`；无上限资源须由其职业规则明确是否允许为负值。
- 每种资源应由职业定义提供初始值；获得、衰减、清空与跨楼层保留规则由对应职业/技能设计定义。

## 角色等级与经验

经验值与等级是独立于 HP、MP 和职业资源之外的长期成长进度，用于驱动角色属性或其他升级收益。

| 项目 | 规则 |
| --- | --- |
| 等级范围 | 最低为 1 级，当前暂定满级为 **30 级**。 |
| 经验来源 | 击败敌人、Boss、完成事件或任务等；具体奖励由内容设计定义。 |
| 升级需求 | 当前为 `required(level) = 10 * level^2`，其中 `level` 为当前等级；等级越高，所需经验越高。 |
| 升级处理 | 获得经验后应循环结算升级，使单次大量经验能够连续提升多个等级。 |
| 满级处理 | 达到 30 级后不再提升等级，也不再累计用于升级的经验进度；仍可保留本局累计获得经验作为战绩统计。 |

### 经验数据与计算约束

- 角色成长的唯一事实来源应为玩家状态中的 `level` 与“当前等级进度经验”；现有 `RunStats.experience` 可继续作为本局累计战绩，不应直接承担升级判定。
- 升级所需经验应由统一函数或等级表按“目标等级”查询，例如 `experienceRequiredForLevel(level)`；不得将 1 至 30 级的需求散落在敌人或界面逻辑中。
- 当前经验需求公式已确定为 `required(level) = 10 * level^2`；每级成长属性、升级奖励和最终节奏仍待平衡。
- 经验进度界面应同时展示当前等级、当前经验和升至下一级所需经验；满级时展示“满级”，不显示下一等级需求。
- 经验奖励与升级结算应记录在战斗/事件日志中，便于玩家理解成长来源，也便于测试验证溢出经验。

### 升级即时效果与奖励选择

- 每次升级都会将当前 HP 上限提升至原值的 1.1 倍（向上取整），并将 MP 回满；当前 HP 不会因此自动回满。
- 每次升级都会触发一次升级奖励选择。若单次获得经验连续升级，必须逐级完成选择，不得跳过奖励。
- 奖励池按职业拆分：所有职业共享“通用基本”和“通用属性”池，再叠加各自注册的职业池。当前 0.1 版本已注册龙骑士池，完整表格与效果见 `doc/dragoon-level-reward-design.md`。
- 每个奖励都有独立权重，初始均为 1；按权重无放回抽取最多 3 项。权重只影响进入候选的概率，不改变奖励效果。
- 表格中标记“一次性”的技能/被动奖励领取后会从该职业池移除；标记“否”的属性与金币奖励可重复领取。带前置条件的奖励只有满足前置后才会进入候选池。
- 当前通用奖励将表格中的“小幅提升”落为 +10 点对应属性；该数值集中在奖励定义中，后续可直接调整而无需修改抽取流程。
- 当前实现中，1 级升 2 级需要 10 点经验，2 级升 3 级需要 40 点经验；达到 30 级后升级需求返回 0。

## 静态属性

### 属性总表

| 分类 | 属性 | 设计职责 |
| --- | --- | --- |
| 基础输出 | 力量 | 可作为近战、武器或指定技能的伤害取值属性。 |
| 基础输出 | 敏捷 | 可作为灵巧、远程或指定技能的伤害取值属性。 |
| 基础输出 | 智力 | 可作为魔法或指定技能的伤害取值属性。 |
| 生存 | 精神 | 提高回复类技能的回复量。 |
| 生存 | 坚韧 | 提高 HP 上限，并提供常驻减伤。 |
| 生存 | 信仰 | 提高 MP 回复速度，并降低 MP 消耗。 |
| 伤害 | 信念 | 提高整体增伤。 |
| 伤害 | 直击 | 提高直击概率；触发后造成固定 **40%** 增伤。当前版本不产生未命中结果。 |
| 伤害 | 暴击 | 同时提高暴击率与暴击增伤幅度。 |

### 主属性与职业

力量、敏捷、智力统称**基础输出属性**。每个职业必须固定指定其中一项为其**主属性**：

- 主属性直接影响该职业的普通攻击伤害。
- 普通攻击不再以通用 `atk` 作为长期规则来源；临时兼容字段可在实现迁移完成后移除。
- 技能不被主属性限制：技能可显式声明其伤害取值属性，可选择力量、敏捷或智力中的任意一项；0.1 未声明时默认使用职业主属性。
- 职业资料必须包含 `primaryAttribute`；`scalingAttribute` 是技能的可选字段，后续技能扩展可据此覆盖职业主属性。

## 战斗结算职责

当前原型已经固定普通攻击与敌人攻击的伤害公式。公式中的比例属性均按整数值处理，概率使用 `[0, 1)` 的随机数判定；各阶段按以下顺序结算。

### 玩家普通攻击

设：

- `P`：职业主属性值。普通攻击取职业定义中的 `primaryAttribute`，当前龙骑士取力量。
- `B`：当前 `might` 增益提供的临时攻击加成总和。
- `A = floor(P / 2) + B`：玩家攻击力。
- `F = floor(enemy.def / 2)`：目标防御折算值。
- `R`：从 `-1、0、1` 中等概率随机取一个值。

伤害按以下顺序计算：

1. 防御后基础伤害：`D0 = max(1, A - F + R)`。
2. 信念增伤：`D1 = round(D0 * (1 + determination / 1000))`。
3. 直击判定：`pDirect = min(1, directHit / 1000)`。触发时 `D2 = round(D1 * 1.4)`，未触发时 `D2 = D1`。当前版本的 `directHit` 只负责直击概率和 40% 增伤，不产生未命中结果。
4. 暴击判定：`pCritical = min(1, criticalHit / 1000)`。
5. 暴击倍率：`M = 1.5 + min(0.5, criticalHit / 2000)`。触发时 `D3 = round(D2 * M)`，未触发时 `D3 = D2`。
6. 最终伤害：`D = max(1, D3)`。

直击与暴击可以在同一次攻击中同时触发，结算顺序为“信念 -> 直击 -> 暴击”，每个乘区单独取整。当前的一击必杀修改器在公式结算后将伤害替换为目标当前 HP，不改变普通公式。

### 敌人攻击玩家

设 `E` 为敌人攻击力，`H = floor(hero.def / 2)`，则敌人的原始伤害为：

`D0 = max(1, E - H + R)`

玩家坚韧减伤后：

`D = max(1, floor(D0 * (1 - min(0.5, tenacity / 1000))))`

因此坚韧最多提供 50% 常驻减伤，且正常伤害不会低于 1 点。无限血量修改器会在受击后将玩家 HP 保持为最大值，但仍记录这次计算出的伤害反馈。

### 属性参与范围

| 属性 | 当前伤害相关规则 |
| --- | --- |
| 力量 / 敏捷 / 智力 | 由职业主属性决定普通攻击取值；技能接入后由技能的 `scalingAttribute` 决定。 |
| 精神 | 当前不参与伤害；预留给回复技能的回复量。 |
| 坚韧 | `maxHp = 20 + floor(tenacity / 10)`，并参与敌人对玩家的减伤。 |
| 信仰 | 当前不参与伤害；影响 MP 自然回复和 MP 消耗。 |
| 信念 | 按 `determination / 1000` 提高玩家最终普通攻击伤害。 |
| 直击 | 按 `directHit / 1000` 提供直击概率，触发时额外乘以 1.4。 |
| 暴击 | 按 `criticalHit / 1000` 提供暴击概率，并将暴击倍率从 1.5 提高至最高 2.0。 |
| 等级 / 经验 / MP / 职业资源 / Gil | 当前不直接改变伤害；后续由成长、技能和装备系统接入。 |

### 回复与资源流程

- 回复技能的基础回复量由技能定义提供，精神作为其主要回复取值属性。
- 坚韧在 HP 上限计算后提供常驻减伤；减伤适用范围（仅直接伤害或包含持续伤害/环境伤害）由防御规则补充。
- 信仰同时参与 MP 自然回复速度与 MP 消耗量修正。消耗下限、是否影响道具消耗及是否影响非 MP 资源，需由资源规则补充。

## 推荐数据结构

以下为设计层的数据形状，字段命名可随实现语言调整：

```ts
type BaseAttribute = 'strength' | 'dexterity' | 'intelligence';

interface StaticAttributes {
  strength: number;
  dexterity: number;
  intelligence: number;
  mind: number;
  tenacity: number;
  piety: number;
  determination: number;
  directHit: number;
  criticalHit: number;
}

interface HeroProgression {
  level: number; // 1 至 30
  experience: number; // 当前等级的经验进度
}

interface JobDefinition {
  // 现有职业字段……
  primaryAttribute: BaseAttribute;
  resources: JobResourceDefinition[];
}

interface SkillDefinition {
  // 伤害技能必填；非伤害技能可省略。
  scalingAttribute?: BaseAttribute;
  potency?: number;
  mpCost?: number;
}
```

玩家运行时状态应同时保存静态属性的**最终汇总值**与其来源（职业基础值、等级成长、装备、临时效果）。若初期不需要完整来源追踪，至少应将“基础值”和“最终值”分开计算，避免存档中固化一次性修正。等级与当前等级经验必须进入存档校验；升级所需经验由规则计算，不应冗余写入存档。

## 实施顺序

1. 扩展职业定义：为每个职业补充主属性，并保留现有的可变职业资源列表。
2. 扩展玩家状态与存档校验：加入等级、当前等级经验和九项静态属性，兼容旧存档的默认值迁移。
3. 将当前击杀奖励接入经验结算：保留 `RunStats.experience` 作为战绩，并以玩家等级进度为唯一升级依据。
4. 建立统一的属性汇总与公式层：普通攻击、伤害技能、回复技能都通过该层取值。
5. 将普通攻击从 `atk` 迁移到职业主属性；为技能增加独立的取值属性声明。
6. 为坚韧、信仰、信念、直击与暴击的当前公式补齐自动化测试；命中失败、技能倍率和装备修正待后续系统接入。
7. 设计职业初始属性、每级成长、技能系数和各属性的数值换算曲线，再进行职业间平衡。

## 待定项

- 九项静态属性的初始值、成长来源与上限。
- 每级成长、升级奖励和 1 至 30 级的最终节奏。
- 技能倍率、护盾、持续伤害和装备修正如何接入最终伤害流程。
- 是否为特定技能或敌人增加独立的命中失败规则。
- 普通攻击是否允许职业定义额外的武器系数或攻击类型。
- 职业资源的跨战斗、跨楼层与死亡时重置规则。
